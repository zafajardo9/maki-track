# Simplify authentication to email + password, clean up dead database weight, keep deployment lean

User's questions went unanswered, so this follows the stated request: the fullest sensible simplification — **email + password only** for sign-in and account creation — plus database cleanup (nothing is actually broken; there is dead weight), with deployment unchanged-and-verified.

## What stays vs. what goes

**Stays** (invisible to users, required by product features): API keys, device-flow login (CLI/MCP), the MCP OAuth server, workspaces/roles/invitations (invitation modal already has a copy-link fallback when SMTP is absent), first-user-becomes-admin bootstrap, cloud gates (Turnstile, disposable email, rate limits), S3/Redis/Sentry/billing optionality.

**Goes**: GitHub/Google/Discord social login, custom OIDC provider, magic link, email-OTP ("email code") sign-in, "Continue as guest", "last used" login badges, OIDC logout special-case.

**Result**: sign-in page = one email+password form; sign-up = one name/email/password form. Works on a fresh deploy with nothing but a database URL. Note the sign-in page will no longer swap the password form for an OTP form when SMTP is configured.

## 1. API (`apps/api`)

- `src/auth.ts`: delete the `socialProviders` block, `account.accountLinking`, and the `anonymous()`, `magicLink()`, `emailOTP()`, `genericOAuth()`, `lastLoginMethod()` plugins. Keep `emailAndPassword`, `organization()`, `bearer()`, `apiKey()`, `deviceAuthorization()`, `adminPlugin()`, `openAPI()`, and all hooks/databaseHooks (first-user-admin, registration gating).
- Simplify registration hooks: drop `isOAuthCallbackPath`/`allowInvitationByEmail` (no OAuth callbacks remain); trim `is-local-sign-in-path.ts` to `/sign-in/email`. Keep the defensive `isAnonymous` checks in hooks — legacy anonymous rows may exist in existing databases.
- Delete `src/utils/custom-oauth-profile.ts`, `src/utils/github-sso-env.ts`, the `src/oauth/` id-token router and its mounting in `src/index.ts`.
- `/api/config` (`utils/get-settings.ts` + `config/response.ts`): remove `hasGithubSignIn`, `hasGoogleSignIn`, `hasDiscordSignIn`, `hasCustomOAuth`, `customOAuthAutoLogin`, `customOAuthLogoutUrl`, `hasGuestAccess`, `disableEmailOtpSignIn`, `hasSmtp`. Keep `disableRegistration`, `disablePasswordRegistration`, `disableWorkspaceCreation`, `disableLoginForm`, `isDemoMode`, `billingEnabled`.

## 2. Web (`apps/web`)

- `routes/auth/sign-in.tsx`: strip social/guest buttons, OIDC auto-login, last-used badges, and the OTP-vs-password conditional — always render the password form. `routes/auth/sign-up.tsx`: strip SSO + guest alternatives.
- Delete `components/auth/sso-providers.tsx`, `components/auth/otp-sign-in-form.tsx`, `routes/auth/verify-otp.tsx`, `routes/auth/check-email.tsx` (orphaned), `fetchers/oauth/get-id-token.ts`, plus tests covering deleted files.
- `use-sign-out.ts` / `user-avatar.tsx`: remove the customOAuthLogoutUrl branch (plain sign-out).
- Make it better: wire the existing-but-unused `use-change-password` hook into Settings → Account as a small "change password" card (requires current password); delete the duplicate `use-send-password-reset.ts`.
- i18n: remove social/guest/OTP keys from `i18n/schema.json` and all 20 locale files; add change-password keys. `pnpm i18n:check` must pass.

## Caveats

- Removing `/api/config` fields is a small breaking API change; the web app ships in lockstep, so only third-party consumers of `/api/config` would notice.
- If any user of an existing instance signed in *only* via GitHub/Google/Discord/OIDC, they would be locked out after this change (defaults have OAuth off, so new/self-hosted instances are unaffected).
- No commits will be made.
